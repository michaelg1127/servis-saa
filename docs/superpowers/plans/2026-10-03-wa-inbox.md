# Inbox WA — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an admin-only "Inbox WA" screen where Claude-extracted WhatsApp drafts (HM, solar, keluhan, servis, NSE) are reviewed and approved into SERVIS SAA by prefilling the existing forms.

**Spec:** `docs/superpowers/specs/2026-10-03-wa-inbox-design.md`

**Architecture:** One new table `wa_inbox` (drafts only). Claude inserts drafts from a logged-in admin Chrome tab via the page's `sb` client. The Inbox screen lists drafts; Approve opens the existing modal/form prefilled; a global `window.pendingInboxId` + `onInboxSaved(table, id)` hook marks the draft approved after the normal submit succeeds.

**Tech Stack:** Vanilla JS, Supabase JS v2 (`sb`), single `index.html` at `C:\Users\upsca\Documents\SERVIS-SAA\index.html`.

## Global Constraints

- **NEVER use the Edit tool on `index.html` JS sections** — Node.js patch scripts only (`replaceFn` brace-depth traversal, `replaceExact` count-verified), CRLF (`\r\n`) in multi-line match strings, `node --check` after each patch (extract `<script>` blocks the same way earlier patches do)
- Admin-only screen; SPV/Operator/MKN views unchanged
- Manual entry flows must behave exactly as before when `window.pendingInboxId` is null
- No keys, phone numbers or credentials in committed files (repo is PUBLIC)
- `payload` is never overwritten; edits go to `payload_edited`
- Unit matching: `units.code` case-insensitive, trimmed (WA writes "k7", "K 7", "K7")
